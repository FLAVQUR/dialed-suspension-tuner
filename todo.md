# Dialed — Task list

This is the working list. [summary.md](summary.md) is the record: what exists, why, and what was learned on the way.

How it is used:
- When an item is done, it gets the date and moves to **Done**, at the end.
- In the same step, whatever is worth keeping goes into `summary.md` (what was built, why it was built that way, what went wrong).
- New ideas go into the section they belong to; anything turned down goes to **Parked by decision**, so it isn't proposed again.

## Secondary

- [ ] **"Possible need for service" signal**: logarithmic decrement/ζ per impact, sag drift between sessions. The setup history it was waiting for exists now — compare runs inside one stretch of `setupEpochs()`, where a drift is not explained by a setup change.
- [ ] *(Low)* **SD card: the bit errors that are left on the link.** What made runs fail turned out to be the driver, not the wires (2026-10-11). What remains is a command the card rejects for its checksum about once a minute (`sdCommand(): crc error` in `/api/debug/log`), which the driver repeats by itself and costs nothing. Only worth the hardware work — a decoupling capacitor at the card socket, the ground return, wire lengths, a scope on the clock line — if that rate climbs.

## Future nice-to-haves

- [ ] *(Idea, 2026-10-08)* **An AI second opinion in the Tuning tab.** On request, send a model what the page has already worked out for the run — the evidence behind the suggestions, the events, the segments, the setup and its history, the rider's notes, the bike's components — and show its reading under the rule-based suggestions, which stay. Not the telemetry itself (megabytes). Open points: the call has to come from the browser (the device has neither the memory nor the flash to spare for TLS) and only works where the browser has internet, so not on the device's own access point; where the API key lives, given the pages are served over plain HTTP; and keeping the answer in the run's `.JSON` so it is still there offline. A first step that needs none of that: a "Copy for AI" button that puts the same summary on the clipboard.
- [ ] **Multilingual UI.** The dashboard is English only. The idea is a UI that can be shown in more than one language, rather than a translation of the strings in place.

## Parked by decision — don't pick up unless asked

- **Sampling at 1000Hz.** 500Hz was taken off this list and done on 2026-10-07; 1000Hz stays here for now. The loop has the headroom for it on paper (it is busy for about a quarter of a 500Hz period), but it doubles what the SD write path has to take, and that path lost rows on its first ride at 500Hz (2026-10-10; fixed on the bench the next day, not ridden since). The option stays selectable in Settings, labelled "1000 Hz (Beta)"; what is parked is the work of testing it and making it dependable.
- **Recording in binary instead of CSV.** Asked about and turned down for now on 2026-10-13. A row is about 100 bytes of text against 30 in the `.CSVB` the device already makes after a run, so recording straight to binary would put a third of the data on the card. It stays CSV because the recovery from a failed write leans on lines of text, the file is what the SD investigation was read from, and a card pulled out of the device opens in a spreadsheet. The two things that would reopen it: 1000Hz, or run size and download time becoming a nuisance.
- **IMU at 3MHz.** Already confirmed to break again; it stays at 400kHz.
- **Checking for internet on the ESP32 itself.**
- **A warning when firmware and dashboard don't match.** Turned down on 2026-10-08: the two are always uploaded together instead (`pio run -t upload` does both).

The device now keeps its libraries' warnings in memory (`/api/debug/log`), which is what made this visible.
